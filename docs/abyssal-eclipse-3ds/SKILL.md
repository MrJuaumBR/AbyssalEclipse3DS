# Abyssal Eclipse — 3DS build brief (prompt to self)

You are building a complete, shippable homebrew game for the **Old Nintendo 3DS (O3DS/O2DS, ARM11 268 MHz, ~64 MB)**. It must also run on New 3DS, but the New 3DS is never the target: everything is budgeted for the old hardware.

## 0. Definition of done
1. `make` with devkitARM + libctru + citro2d produces `AbyssalEclipse.3dsx` (and a `.cia` recipe is documented).
2. Game logic compiles on a host g++ with no 3DS headers and passes the headless soak test (`host_test/`).
3. `platform_3ds.cpp` passes `-fsyntax-only` against the stub headers in `host_test/stubs/`.
4. Every feature in `references/feature-checklist.md` is marked IMPLEMENTED, APPROXIMATE (with the reason) or TODO (with the reason). Never leave a feature unlisted.
5. The final message tells the user plainly what was verified (host test) and what was NOT (real hardware, real devkitPro compile).

## 1. Source of truth
- Design document (print doc, v0.1) and the interactive HTML mockup are the spec. Data (137 spells, 25 enemies, 195 UI strings, lore, pt-BR) is generated by `tools/gen_data.py` from the mockup export. **Never hand-edit `source/data_gen.cpp`; edit the generator.**
- When the document and the mockup disagree, the print design document v0.1 wins (e.g. 137 spells, not the 30 relics of mockup revision 1). Mention the choice.
- Content not specified by the user (e.g. level names for seasons other than Forest) is a clearly marked placeholder in data, listed in the README.

## 2. Hard hardware rules (details: `references/hardware-budget.md`)
- Single 400x240 top gameplay screen, 320x240 touch bottom screen. **3D slider off** (`gfxSet3D(false)`).
- Fixed pools, **zero heap allocation after init**. Caps: 48 enemies, 72 projectiles, 48 gems, 32 fx, 12 zones.
- **One 256x256 RGBA8 atlas**, baked procedurally at boot (no external art files needed). One texture = one batch.
- <= 1200 draw objects/frame, <= 2 full-screen alpha layers, no per-frame string formatting on hot paths beyond HUD numbers.
- Fixed 60 Hz logic step, adaptive: if a frame is late, at most 2 catch-up steps, then drop to a 30 Hz mode automatically (and offer a manual 30 FPS option for battery).
- Never use core 2/3 (N3DS-only). Audio via ndsp with graceful silent fallback if `dspfirm.cdc` is missing.
- SD writes only on events (menu confirm, run end, options change), atomic write (tmp + rename), CRC-checked, versioned save.
- Handle `aptMainLoop()` returning false and sleep/suspend by saving and exiting cleanly.

## 3. Architecture rules
- `source/` game code includes **only** `platform.h`; all libctru/citro2d/ndsp lives in `platform_3ds.cpp`. A second backend `platform_null.cpp` exists for host tests.
- Data-driven: spells = table of `{kind,a,b}` effect triples interpreted by one engine (`spells.cpp`); enemies = stat table + behavior bitmask; localization = key tables with English fallback; unknown keys never crash.
- Deterministic sim: own xorshift RNG seeded per run, so debug actions and the soak test are reproducible.
- Validate build capacity (12) and stat points before continuing a phase; death resets transient run state but never touches catalog discovery.
- Never silently truncate spell descriptions, stats, enemy specials or lore: the text renderer word-wraps and scrolls instead.

## 4. Feature brief (condensed; full list in `references/feature-checklist.md`)
Modes: Campaign (season -> levels 1-1/1-2/1-3 = 10/15/20 waves, locked progression), Endless (replay a season, best wave), Catalog (spells + bestiary with discovery + found counts + lore), Customize (hat/face/color, cosmetic only), Weapon select (dagger, bow, axe, staff; chosen weapon is the run's first spell), Options (language en/pt-BR, music/SFX volume, 30 FPS cap, credits), Debug (simulate wave end, boss fight, force spell, clear spells, simulate death, reset).
Run loop: PLAY -> WAVE CLEARED -> ALLOCATE (1 point per level-up across STR/RES/SPD/LUCK/INT) -> SPELL CHOICE (3 offers by rarity weights 60/28/10/2, +LUCK rare bonus; at 12/12 slots upgrade an owned spell instead) -> PLAY. BOSS phase on the final wave of a level (and every 10th endless wave). DEATH resets the run; Phoenix Down revives once.
Seasons: FOREST(earth+air) DESERT(fire+earth) SNOW(water+air) MOUNTAIN(earth+air) ECLIPSE(blood+lightning). Spell pool per run = 22 global + element-locked spells of the season's two elements + 5 season exclusives. Each season has a gimmick (Forest brambles block shots and slow everyone, etc.).
Controls: D-pad/Circle Pad move and navigate, A confirm, B back, L/R switch tabs, START pause, SELECT debug panel, touch for tabs/stat rows/offers. Auto-attack nearest enemy.

## 5. Workflow (always in this order)
1. Re-read `references/feature-checklist.md`; pick the next TODO items.
2. Change data only through `tools/gen_data.py`; run it.
3. Build host test: `make -C host_test run` (g++ -O2 -Wall -Wextra, must be warning-free).
4. Syntax-check the 3DS backend: `make -C host_test syntax3ds`.
5. Update the checklist statuses and the README known-limitations list.
6. Report honestly. If devkitARM is unavailable, say it was not compiled for ARM.

## 6. Balance constants (single place: `source/balance.h`)
Base HP 60, base stats STR8 RES5 SPD4 LUCK3 INT5 (bonus = allocated points x per-point value, base is the zero point), expNeed(l)=10+(l-1)*5, wave length 40 s, i-frames 0.6 s, speed words VERY SLOW 14 / SLOW 22 / LOW 28 / NORMAL 36 / FAST 52 / VERY FAST 70 px/s, attack-rate words 2.4/1.6/1.3/1.0/0.7 s, ranges TOUCH / HIGH 140 px / VERY HIGH 190 px. Tune only here.
